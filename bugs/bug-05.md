# BUG-05: Гарчиг, Зохиолч талбар хоосон эсвэл зөвхөн хоосон зайтай байхад ном нэмэгдэж, «Ном нэмэгдлээ» гэж амжилттай гэж мэдэгдэнэ

Энэ тайланд нэг шалтгаантай (сервер Гарчиг/Зохиолчийг шалгадаггүй) хоёр ажиглалтыг нэгтгэв: session-report-ийн BUG-05 (хоосон форм) ба BUG-13 (зөвхөн хоосон зайтай гарчиг).

Орчин: Уншлагын жагсаалт v2.0, Google Chrome 154, macOS 15.6, curl 8.7.1, 2026-10-16

Урьдчилсан нөхцөл: node app.js-ийг шинээр асаасан (анхны 3 ном)

## Дахин гаргах алхам

1. Хөтөчөөр http://localhost:3000 хаягийг нээнэ.
2. Гарчиг, Зохиолч, Он гурван талбарыг хоосон үлдээгээд «Нэмэх» товчийг дарна.
3. Гарчиг талбарт зөвхөн 3 хоосон зай (space), Зохиолч талбарт `test`, Он талбарт `1212` гэж бичээд «Нэмэх» товчийг дарна.
4. Терминалд дараах командыг ажиллуулна:
   `curl -i -X POST http://localhost:3000/api/books -H 'Content-Type: application/json' -d '{}'`

Хүлээгдэж байсан: Эрүүл ухаан — Гарчиг, Зохиолч заавал бөглөх талбар байна. Хоосон эсвэл зөвхөн хоосон зайтай утгыг татгалзаж, «Гарчиг оруулна уу» гэх мэт алдааны мессеж гаргана. API нь `400 Bad Request` буцаана.

Бодит үр дүн: 2-р алхамд «Ном нэмэгдлээ» мессеж гарч, гарчиг, зохиолчгүй хоосон мөр нэмэгдэнэ, Он баганад «0» харагдана, «Нийт ном: 5» болно. 3-р алхамд гарчиг нь хоосон харагдах мөр нэмэгдэнэ (Зохиолч «test», Он «1,212»). 4-р алхамд `HTTP/1.1 201 Created`, `{"result":"OK","id":6}` — хоосон ном API-аар ч хадгалагдана.

Ноцтой байдал: Major — өгөгдлийн бүрэн бүтэн байдал алдагдана: жагсаалтад утгагүй хоосон мөрүүд хуримтлагдаж, статистикт тоологдоно. Хэрэглэгчид алдаа мэдэгдэхгүй, харин амжилттай гэж худал мэдэгдэнэ.
