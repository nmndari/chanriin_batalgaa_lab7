## Дүгнэлт
Fed-Ex аялал хамгийн үр дүнтэй байсан бөгөөд өгөгдлийг оролтоос API, хүснэгт, статистик, хайлт хүртэл дагаж BUG-02, BUG-03, BUG-04, BUG-10, BUG-11-ийг илрүүлсэн.

Saboteur аялал curl ашиглан BUG-08, BUG-09, BUG-15-ийг илрүүлж, BUG-05 болон BUG-10-ийг API түвшинд баталгаажуулсан.

Supermodel аяллаар BUG-06, BUG-07, BUG-14, Couch Potato аяллаар BUG-05, Prior Version аяллаар BUG-01 илэрсэн.

Charter-аас гадуур DevTools-д өөр аппын localhost:4200 хүсэлтүүд холилдох, товчнуудад hover эффект байхгүй байх, хайлтын үед «Нийт ном» үр дүнгийн тоог биш нийт тоог харуулах зэрэг асуудал ажиглагдсан.

Серверийг дахин асаасны дараах өгөгдлийн хадгалалт, олон таб болон хэрэглэгчийн ажиллагаа, accessibility, гар утасны дэлгэц, гүйцэтгэл, HTTP аюулгүй байдлын header-үүд шалгагдаагүй үлдсэн тул эдгээрийг дараагийн session-ий charter болгоно.

Лаб 1-ийн Playwright автомат тестээр BUG-01 (/old холбоосын 500 статус), BUG-02 (мөрийн тоо статистиктай зөрөх), BUG-05 (хоосон форм), BUG-07 (устгасны дараах мессеж), BUG-10 (NaN он)-ийг барих боломжтой байсан.

Мөн BUG-04, BUG-11-ийн хайлтын үр дүнг зөв assert бичсэн тохиолдолд, BUG-08, BUG-09-ийн API алдааг Playwright-ийн request API-аар статус код болон хариуг шалгаж илрүүлж болох байсан.

BUG-15 (давхар нэмэх)-ийг товчийг олон дарж мөрийн тоог шалгавал автоматаар барих боломжтой, харин BUG-03 (оноор хайх) нь шаардлага тодорхойгүй тул хүний дүгнэлт шаардана.

Харин BUG-06-ийн «1,971» гэх оны формат, BUG-14-ийн урт гарчгаас хүснэгт эвдрэх зэрэг харагдах байдлын согогийг Playwright тест барихгүй — хэн ч ийм assert бичдэггүй, screenshot тест ч анхнаасаа алдаатай байсан төлөвийг baseline болгон авах тул зөвхөн хүний нүдээр олдох байсан. Иймээс автомат тест нь урьдчилан тодорхойлсон хүлээгдэх үр дүнг шалгаж регрессээс хамгаалдаг бол exploratory тест нь урьдчилан таамаглаагүй согогийг илрүүлэхэд илүү үр дүнтэй гэж дүгнэв.
